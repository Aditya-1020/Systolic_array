# Memory Mapping
- IMEM at `0x0000_0000`. ibex fetches first instr from `boot_addr_i[31:8] + 0x80` (keep in vector table in 0x00-0x7F)
- DMEM is at `0x100_0000`
- CSR window is at `0x4000_0000`, 128 bytes

- IMEM seperate from DMEM, `Icache=0` and no D-cache so no coherence logic
- DMEM is 64bits wide. One DMA beat is one array row (8xint8) so CPU shares same words through byte strobes
- DMEM has one read and write port
    - R: CPU loads, DMA reads
    - W: CPU stores, DMA writes
    - Each port uses 2-way RR-arbiter
    - DMA read and write never colide
    - Check: quantized mode should be able to run one row per cycle
- Array controlled over APB, OBI-to-APB bridge used
- `o_irq` (from array), `irq_external_i` (to ibex). SW cleared by writing `0x10` to STATUs
- Simple SRAM pins, en, we, be, addr, wdata, rdata. Read data valid 1 cycle after enable.
- Use LowRISCV ibex-top simple interface
- Apple tie-offs
    - *_intg_i, data_tag_i, scramble_*, debug_req_i, ram_cfg_* and hart_id_i go to 0.
    - scan_rst_ni and test_en_i go to their inactive levels.
    - boot_addr_i goes to IMEM_BASE.
- DMEM size: `fakemram130_128x64` is 1KB, Plan 8-16KB (several banks), Bank on low word-addr bits inside `dmem_arb`
